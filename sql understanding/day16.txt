What is LEFT JOIN?
A LEFT JOIN returns:
✅ All rows from the left table
✅ Matching rows from the right table
✅ If there is no match, SQL returns NULL for the right table columns

Visual Representation
Suppose we write:
FROM employees_join e
LEFT JOIN departments d
The left table is:
employees_join
The right table is:
departments
SQL says:
"Return ALL employees."
Even if a department doesn't exist.

Why COUNT(emp_id)?
Because:
COUNT(*)
would count the Marketing row as 1.
But
COUNT(e.emp_id)
counts only non-NULL employee IDs.
This is a very common interview question.

COUNT(*) vs COUNT(column)
Suppose Marketing has no employees.
LEFT JOIN creates:
department
emp_id
Marketing
NULL

Now compare:
COUNT(*)
Returns:
1
because the row exists.
But
COUNT(emp_id)
Returns:
0
because NULL values are not counted.
⭐ Interview Tip: When counting matching rows after a LEFT JOIN, use COUNT(right_table.primary_key) instead of COUNT(*).

Interview Questions (with Answers)
1. What is a LEFT JOIN?
Answer:
A LEFT JOIN returns all rows from the left table and matching rows from the right table. If there is no match, the right table columns contain NULL.

2. What is the difference between INNER JOIN and LEFT JOIN?
INNER JOIN
LEFT JOIN
Returns only matching rows
Returns all rows from the left table plus matching rows from the right
Unmatched rows are excluded
Unmatched rows appear with NULL values


3. Why do NULL values appear in a LEFT JOIN?
Answer:
Because SQL could not find a matching row in the right table.

4. How do you find rows with no match?
Answer:
Use a LEFT JOIN and filter for NULL in the right table.
SELECT e.name
FROM employees_join e
LEFT JOIN departments d
ON e.department_id = d.department_id
WHERE d.department_id IS NULL;

5. Why use COUNT(column) instead of COUNT(*) after a LEFT JOIN?
Answer:
COUNT(column) ignores NULL values, so it correctly counts only matching rows. COUNT(*) counts every returned row, even when the joined columns are NULL.
